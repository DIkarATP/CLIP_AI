# CLIP AI — Twitch Connector / Clip Hunter

Локальное Windows-приложение для подключения Twitch API, управления источниками Twitch, мониторинга LIVE-записей и анализа записей с помощью Hunter/YAMNet.

> Этот репозиторий собран из переданного архива проекта. Документация описывает только функции, которые подтверждаются кодом этой сборки. Не все ранее обсуждавшиеся функции и интерфейсы входят в этот пакет.

## Возможности этой сборки

Подтверждено исходным кодом:
- локальный HTTP-сервер, по умолчанию `127.0.0.1:8766`;
- получение Twitch App Access Token с помощью Client ID и Client Secret;
- поиск/получение публичных Twitch LIVE-стримов;
- сохранение списка источников в `data/sources.json`;
- фоновый Worker, проверяющий включённые и подтверждённые Twitch-источники примерно каждые 30 секунд;
- запись разрешённых LIVE-потоков через Streamlink в `recordings/*.ts`;
- создание MP4-фрагментов из локальных TS-записей через FFmpeg;
- Hunter v3: ранжирование звуковых пиков, контраста, динамики, zero-crossings и видеосмен сцен;
- отдельный YAMNet-анализ аудиособытий (смех, крики и другие звуковые классы);
- локальный предпросмотр записей, включая remux TS в MP4 для seekable preview;
- отдельное серверное хранилище оценок эпизодов/обратной связи, если вызывается соответствующий API.

## Требования

- Windows 10/11.
- Python 3.11 x64 и Python Launcher (`py`).
- Интернет для установки пакетов и обращения к Twitch API.
- Streamlink и yt-dlp — устанавливаются через `requirements.txt`.
- FFmpeg и ffprobe — нужны для создания клипов, подготовки предпросмотра и некоторых анализов.
- Для YAMNet: дополнительные пакеты TensorFlow CPU, TensorFlow Hub, NumPy и SoundFile.

## Установка

1. Скачайте ZIP репозитория и распакуйте его в отдельную папку, например `D:\CLIP_AI`.
2. Установите Python 3.11 x64 с Python Launcher.
3. Скопируйте `.env.example` в `.env`.
4. Заполните Twitch Client ID и Client Secret в `.env` (см. ниже).
5. Запустите `setup.bat` и дождитесь окончания установки базовых зависимостей.
6. Установите FFmpeg и добавьте его `bin` в PATH либо задайте `CLIP_AI_FFMPEG_BIN` в `.env`.
7. Запустите `start.bat`.
8. Откройте `http://127.0.0.1:8766`.

### Важное замечание об установщике

`setup.bat` из исходной сборки устанавливает зависимости через `py -3 -m pip` в выбранное Python 3 окружение пользователя. Если на компьютере несколько Python-окружений, проверьте, куда указывает `py -3`. Не запускайте установку повторно без необходимости. GPT/помощник должен сначала проверить `py -3.11 --version`, `py -3.11 -m pip show streamlink yt-dlp psutil` и наличие FFmpeg.

## Настройка Twitch API

1. Создайте Twitch Developer Application в Twitch Developer Console.
2. Скопируйте Client ID и Client Secret.
3. Создайте `.env` на основе `.env.example`.
4. Укажите:

```dotenv
TWITCH_CLIENT_ID=ваш_client_id
TWITCH_CLIENT_SECRET=ваш_client_secret
```

Не добавляйте кавычки без необходимости. Не публикуйте `.env`, не присылайте его в чат и не добавляйте в Git.

Проверка подключения: `http://127.0.0.1:8766/api/twitch/status`.

## FFmpeg

Сервер ищет FFmpeg:
1. в системном `PATH`;
2. в папке, указанной `CLIP_AI_FFMPEG_BIN`;
3. в нескольких стандартных локальных папках, включая `D:\CLIP_AI\tools\ffmpeg\ffmpeg-9.0.2-essentials_build\bin`.

В каталоге должны находиться `ffmpeg.exe` и `ffprobe.exe`. Проверка в CMD:

```bat
ffmpeg -version
ffprobe -version
```

Если FFmpeg уже лежит на диске D, не скачивайте его повторно — укажите существующую папку через `CLIP_AI_FFMPEG_BIN` или добавьте её в PATH.

## Запуск

Запустите `start.bat`. В этой сборке:
- порт по умолчанию `8766`;
- автозапуск Worker выключен (`CLIP_AI_AUTOSTART_WORKER=0`);
- Worker запускается вручную из интерфейса;
- локальный сервер слушает `127.0.0.1`, а не все сетевые интерфейсы.

Оставьте окно сервера открытым, пока используете приложение. Чтобы остановить сервер, нажмите `Ctrl+C` в его окне. Остановка Worker и остановка сервера — разные действия.

## Папки и данные

Создаются сервером при запуске:
- `data/` — источники, статусы, метаданные, кэш и обратная связь;
- `recordings/` — исходные записи;
- `clips/` — созданные MP4-клипы;
- `preview_cache/` — подготовленные файлы предпросмотра.

Эти папки намеренно исключены из Git. Они содержат пользовательские данные и большие медиафайлы. Не удаляйте их при обновлении проекта.

## Hunter и YAMNet

### Hunter v3

Hunter v3 оценивает кандидаты по аудиосигналам и числу видеосмен сцен. Это эвристическое ранжирование, а не понимание игрового сюжета, речи, сарказма или эмоций. В ответе API явно указывается, что семантическое распознавание речи/эмоций/игрового контекста не подключено.

### YAMNet

YAMNet — отдельный анализатор звуковых классов. Он может отмечать звуки, похожие на смех, крик, возглас и другие классы. Он не доказывает эмоцию человека и не определяет, что происходит в игре.

Для установки зависимостей YAMNet используйте `install_yamnet.bat`, затем `test_yamnet.bat`. Установка требует Python 3.11 x64 и интернет. При первом анализе TensorFlow Hub может загрузить модель и сохранить её в локальный кэш.

## API

Основные маршруты, обнаруженные в `server.py`:
- `GET /api/health`
- `GET /api/system/status`
- `GET /api/twitch/status`
- `GET /api/twitch/streams`
- `GET /api/sources`
- `GET /api/clips`
- `GET /api/worker/status`
- `GET /api/hunter/episode-feedback`
- `POST /api/hunter/analyze`
- `POST /api/hunter/yamnet`
- `POST /api/hunter/audio-events`
- `POST /api/clips/create`
- `POST /api/worker/start`
- `POST /api/worker/stop`
- `PATCH /api/clips/{name}`
- `PATCH /api/sources/{id}`

Параметры и ответы смотрите непосредственно в `server.py`; контракт может меняться между версиями.

## Безопасность и права на контент

- Не коммитьте `.env`, Client Secret, OAuth-токены, приватные ссылки, личные записи и клипы.
- Не используйте чужие ключи и не публикуйте содержимое `.env`.
- Включайте подтверждение прав только для контента, на запись и переработку которого у вас есть разрешение.
- Наличие Twitch API-доступа само по себе не предоставляет авторских прав на запись, скачивание, переработку или публикацию чужого контента.
- Не открывайте локальный сервер в интернет без отдельного проектирования аутентификации и защиты.
- Перед публикацией проверьте Git diff и содержимое архива на секреты.

## Известные ограничения этой выгрузки

- В предоставленном `index.html` и `server.py` не обнаружен маршрут `/api/hunter/episodes` и интерфейс кнопки «Собрать игровые эпизоды». При этом сервер содержит endpoint чтения `/api/hunter/episode-feedback`. Поэтому не следует считать, что UI Episodes V1.1 полностью присутствует в этом архиве.
- Семантическое понимание игрового контекста не реализовано.
- YAMNet классифицирует аудиособытия, а не человеческие эмоции.
- Worker этой версии записывает Twitch LIVE; не следует считать, что он автоматически скачивает произвольные старые VOD.
- Совместимость MP4 в селекторе записей следует проверить на реальной установке; текущая выгрузка сама по себе не подтверждает, что каждый MP4 отображается в каждом списке интерфейса.
