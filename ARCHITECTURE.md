# Архитектура CLIP AI

## Общая схема

- `index.html` — веб-интерфейс приложения.
- `server.py` — локальный HTTP API, Twitch OAuth app token, управление источниками, Worker, записи, клипы и анализ.
- `ai/yamnet_detector.py` — отдельный модуль классификации аудиособытий YAMNet.
- `requirements.txt` — базовые Python-зависимости.
- `setup.bat` — установка базовых зависимостей.
- `start.bat` — запуск локального сервера.
- `install_yamnet.bat` — отдельная установка зависимостей YAMNet.

## Потоки данных

1. Пользователь добавляет Twitch-источник в интерфейсе.
2. Сервер сохраняет список в `data/sources.json`.
3. Worker проверяет включённые и подтверждённые Twitch-источники.
4. При обнаружении LIVE запускается Streamlink, который пишет поток в `recordings/`.
5. Hunter может анализировать запись, создавать клипы и сохранять метаданные.
6. YAMNet отдельно классифицирует аудиособытия и возвращает временные интервалы.

## Основные файлы данных (локальные, не коммитить)

- `data/sources.json`
- `data/clip_statuses.json`
- `data/clip_metadata.json`
- `data/hunter_audio_cache.json`
- `data/hunter_episode_feedback.json`
- `recordings/*`
- `clips/*`
- `preview_cache/*`

Фактический набор файлов зависит от того, какие функции запускались.

## Локальные порты

- Основная сборка в этой выгрузке: `8766`.
- Сервер слушает loopback `127.0.0.1`.
- Автозапуск Worker выключен по умолчанию.
